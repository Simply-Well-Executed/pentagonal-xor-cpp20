For each pinned source SHA, in dependency order:

1. Fetch original source into a separate fresh scratch-pad-point0;
   independently SHA-256 fingerprint every file, parse active PowerShell
   source, and record a canonical sorted custody TSV.
2. Run that PR's own native whole suite with separate external evidence.
   For older PR #34, run its native TRIFORCE pipeline and root/shared/
   installed consumer native suite. For PR #95, run full EXCITE file,
   six subproject and repository laps, replay the QCHAIN, then compile
   EXCITED native C++20 and verify its Markdown/TSV receipts.
   These are not falsely described as identical test suites.
3. Recompute every source file hash and file count after execution;
   mutation fails closed. Record a supervisory DOVIA.SIGNAL.3 single-
   observer receipt using the current exact radical FOV bounds;
   this derived witness is not another sensor or authority.
4. Recheck each pinned PR head/base SHA after all tests.

If any individual PR fails, test other PRs independently to preserve
diagnostic coverage, but refuse real MATCHB0Xn9 admission. Never borrow
another PR's green result. Historical failed runs remain evidence.

## Opposing BIDI processes and one simplex lane

An admitted manifest contains 1 to 9 unique records:

pr_number TAB source_sha40 TAB custody_sha256 TAB whole_receipt_sha256

Two separate PowerShell processes start together, one FORWARD in stack
order and the other REVERSE. A single exclusive Windows file-sharing
lock is held for each complete directional traversal: no simultaneous
occupancy and no overtaking. The other process waits for release.
Independent head/tail TSV hashes and lease receipts are verified
against the original manifest. This is a software serial-lane
simulation, not literal optical fiber full duplex, railroad control,
physical cameras, GPS, or Unicode directional text reordering.

## Negative canaries and governance

Exactly 9 circuits are supported, but 10 are always rejected. Duplicate,
missing, malformed, or changed circuit IDs and receipts fail closed.
Synthetic tests require 9 accepted, 10 refused, duplicates refused;
these tests never count as real PR qualification.

The workflow .github/workflows/MATCHB0Xn9.yml runs on native Windows
after pushes to the review branch, uses pinned GitHub SHA sources and
read-only repository permissions. No Python, Node, checkout action,
automatic PR merge, force push, release, or deployment.

RELEASE=HOLD remains mandatory.
