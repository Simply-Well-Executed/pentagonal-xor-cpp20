# COREAO accessible starchart

Status: EXPLORATORY; RELEASE=HOLD. Original project guidance: 0BSD. No third-party character artwork or text is relicensed.

## Requirements

- Preserve complete node inventory and stable namespaced identifiers. Selection highlights; it never removes nodes. Separate original characters, fanon, experimental reflections and independent avatars. No popularity gate.
- Provide a full plain-text ledger and explicit selected-node name, provenance, polarity and narrative role. Color is supplemental. Never infer consent or identity from gaze, position or selection.
- Use predictable visible buttons for rotation, zoom, reset, selection and RADICAL steps; no drag-only actions. Support keyboard, touch and switch activation. Preserve reserved AIRGAP. Apply PENTAPI single exposure to actions, not data. Keep full audit available.
- Target WCAG 2.2 AA: normal text contrast >=4.5:1, large text >=3:1, essential nontext graphics >=3:1, keyboard operation, visible unobscured focus, text resize to 200%, reflow for controls and ledger, text spacing overrides, target size >=24 CSS px subject to criterion exceptions. Project preferences: 18px default text, 7:1 text contrast where feasible, 44px minimum control targets, 1.5 line spacing, manual movement by default. Use clear headings, concise plain language, readable type and horizontal labels where practical. Do not require color discrimination or animation.
- Keep geometry and ledger independent. Reverse NINZA is a representation operation, not a claim of canonical gender change. Rainbow arrow uses nearest geometric target, with stable ID tie-break; show target in text. White Horse and Rainbow Dragon remain independent.

## Acceptance tests (not executed)

Check complete roster before and after selection, zoom, rotation and movement; compare source IDs and counts; verify nearest target and ties; test keyboard-only access, screen reader names/status, 200% magnification, 320 CSS px reflow of controls and ledger, contrast, touch, switch scanning, eye control and reduced motion on real devices. No certification claimed. Native implementation must follow existing repository build and license policy; no new runtime dependency is authorized by this document.
